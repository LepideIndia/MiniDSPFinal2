- Detection design (human to review): precedence on overlap is Payment Card > Email > UK NINO > UK Phone, then earlier start. Digits joined by a single space/hyphen count as one run, so a phone/card inside a longer digit run is rejected (e.g. a card followed by " 07700 900123" in plain TXT is rejected, as a known trade-off). UK geographic phones accepted only as 11 national digits starting 01/02 (10-digit geographic forms are not detected). NINO: format only, suffix A–D optional, a trailing single stray letter makes it malformed. Email: ASCII only, no quoted/IP-literal forms.
- Masking: Email `a***@domain` (local part fully hidden if under 3 characters; domain is kept); Phone all digits `*` except last 3; NINO first two letters + `*`; Card all digits `*` except last 4. Separators are preserved. Masked example is taken from the first accepted occurrence of each type.
- Upload decisions: validation order is size, filename, extension, binary, UTF-8. Status codes: 400 empty/bad filename/missing/multiple files/bad multipart/bad Content-Length; 401 not signed in (checked first); 413 over 1,048,576 bytes (early on Content-Length > 1 MiB + 64 KiB envelope allowance, and by counting real bytes while streaming the body); 415 not multipart, wrong extension, binary (NUL/other control bytes or DEL; TAB/LF/CR allowed), invalid UTF-8; 500 generic (including save failure). Leading UTF-8 BOM is accepted and stripped (counted toward the size limit). UTF-16 files are rejected. Filename: path stripped (both separators), control/bidi/zero-width characters removed, trimmed, **1-255 code points with at least one character before the extension** (corrects the earlier "11 to 255" typo in this log; the code was already right and matches the DB CHECK); double extension judged on the last one (`x.exe.csv` OK, `x.csv.exe` rejected). Exactly one field, named `file`. `findingCount` = total matches (sum of all `matchCount`), not number of types: confirm this is what the dashboard should show.
- Milestone 2b design: no service-role key is used anywhere (the `SUPABASE_SERVICE_ROLE_KEY` line is no longer in `.env.local`; the key was pasted into chat earlier and should be rotated). Writes happen only through `save_scan()` with the user's own session; users get SELECT-only on `scans`/`findings`, `anon` gets nothing, so scans are append-only (no user update/delete). `save_scan` is SECURITY DEFINER with `search_path = ''`, uses `auth.uid()`, validates type/risk pairing, count, duplicates and that `masked_example` looks masked for its type (rejects a raw email/phone/NINO/card), and derives scan risk and `finding_count` itself.
